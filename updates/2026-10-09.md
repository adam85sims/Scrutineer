# Update — 2026-10-09

## Headline

Renamed the project **Sentinel → Scrutineer**, and prepared the first public release.

## What changed

- Brand, distribution, import package and console scripts are now Scrutineer /
  `scrutineer-agents` / `scrutineer` (`scrutineer-run`, `scrutineer-serve`).
- 1603 substitutions across 117 files, plus 6 path moves: `src/sentinel` → `src/scrutineer`,
  `tests/sentinel` → `tests/scrutineer`, `.sentinel/` → `.scrutineer/`,
  `sentinel-web.yaml` → `scrutineer-web.yaml`, and two static assets.
- Version 0.2.0 → 0.3.0. `__version__` now reads from distribution metadata, so
  `pyproject.toml` is the single source of truth.
- Deliberately *not* renamed: phrases where "sentinel" is the generic term of art
  (the sentinel value in `web/services/stream_service.py`), and mentions of Microsoft
  Sentinel / SentinelOne / Whitehat Sentinel as competing products. The dated diaries under
  `updates/` are untouched — rewriting a claim log would falsify this project's own evidence.

## Verified

- Test suite: **647 passing** (656 collected; 9 browser e2e tests run in their own CI job).
- `ruff check src/ tests/`: clean.
- CI green on `main` — the five most recent runs, including the docs-only commit `b9d4764`.
- Wheel `scrutineer_agents-0.3.0-py3-none-any.whl` contains `scrutineer/`, `governance/` and
  `common/`; `twine check` PASSED on both the wheel and the sdist.
- `scrutineer run --path examples/basic_scenario.yaml` → PASS, exit 0; the unhandled-chaos
  scenario → FAIL, exit 1.

## Found while doing it

- `click.version_option(package_name=…)` must name the **distribution**, not the import
  package. Wrong value raised `RuntimeError: 'scrutineer' is not installed` on `--version`
  only — the suite never exercises the console entry point, so it stayed green over a broken
  CLI.
- Reinstalling under a renamed package leaves the previous distribution's console scripts and
  `*-dist-info` in `.venv`; they had to be removed by hand.
